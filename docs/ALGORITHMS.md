# 算法与 CPU 计算说明

本文件描述 SC23 已有实现，便于维护者定位公式与代码。它不把设计目标、离线测试或早期模型建议冒充实机验证。
运行时是本地 C/汇编程序；Codex、Claude、DeepSeek 参与开发和审核，不是每帧在线推理服务。

## 1. 轮询、游戏更新与动画相位是三个量

入口是 `PollingThreadProc`。worker 使用 waitable timer：已观测到游戏更新节奏时申请约 2 ms 等待，否则约 4 ms；
异常路径还有回退等待。这是轮询安排，受 Windows 调度影响，不是每个渲染帧都严格执行一次的保证。

- `CopydogObserveCadence` 根据游戏累计游玩毫秒变化和墙钟差估计更新步长；它不把游玩毫秒等同渲染帧计数。
- `CopydogAdvanceFrame` 比较原生动画轨、相位、持续时长等字段；重复样本不刷新原始墙钟时间。
- 连续样本估计动画推进速率，合法测量以旧值和新值各一半平滑；时钟变化、过期、回退和对象变化单独处理。
- 若时间基准或装备有效段不可用，返回等待/未知，不凭显示 FPS 伪造精确时机。

因此，85 FPS 的 `1000/85 ≈ 11.76 ms` 只是名义参考。实际计算使用已观测的游戏更新间隔；
这个间隔也只是下一次更新的估计，不能保证突发卡顿不会跳过可行窗口。

## 2. 当前生产弹反链与数据

`CheckFrameTargets → TryFrameAutomaticParry → TryDiagnosticParry → DiagnosticPressCurrent → DispatchDefense`。

当前路径以原生攻击 episode、武器/手持状态、许可候选、时间窗和最终状态检查决策。
可见动作 ID 暂时仍是移动，不自动否决已开始的原生攻击；取消、退休槽回读、装备变化和同 ID 新一轮攻击有独立状态处理。
一次攻击只有实际进入提交尝试才消耗对应机会，失败的原生尝试也占用本轮自动动作仲裁。

`CdDynamicEligibility` 是静态资源许可候选，`CdDynamicTargets` 保留伤害/许可相关资料，
`CdDynamicTools` 提供自身弹反工具的资源有效段。它们不是同一种“实际武器首次碰到玩家”的测量。
当前生产弹反不调用历史求解器的 CCD 接触授权；`*ForOffline` 入口保留作历史比较。

## 3. 从原生相位换算剩余候选时间

除特别说明外，本节所有时间均用毫秒。设：

| 符号 | 含义 |
|---|---|
| `p` | 最新原生动画当前相位，单位秒 |
| `r` | 动画时间相对于墙钟的推进速率 |
| `a` | 距该原生样本时间基准的墙钟年龄 |
| `b,e` | 资源许可段开始/结束，按动画时间换算成毫秒 |
| `h` | 预计下一次更新的墙钟间隔 |

`DiagnosticTimingPlan` 计算：

~~~text
c0 = (b - 1000*p)/r - a
c1 = (e - 1000*p)/r - a
~~~

已过期的段被跳过，开始时间可以裁到现在。样本过期、速率无效、工具不匹配等不进入可靠时间计划。
如果整段许可过长，无法落入自身有效段，代码可以退化为明确标记的 `onset-only` 单点候选；
这不是求得真实伤害接触 TTI。

## 4. 自身工具有效段与本地延迟

`FrameSelfActivation` 从资源表读取有效段 `[s0,s1)`，并形成用于调度的有效段 `[S0,S1)`。
没有统一固定的“所有盾牌提前 14 帧”规则。

- 少于三次本地观测时，用 `ceil(2*h)` 作为显式调度先验，推迟有效段开始；这是先验，不是已测得的输入延迟。
- 有足够本地观测后，对每个提交到动画观测延迟 `q_i`，采用当前代码的 8 ms 余量，
  同时使用观测到的自身动画速率 `r_i`，取各个有效段的交集：

~~~text
lower_i = max(0, q_i - 8)
upper_i = q_i + 8
S0 = max_i(upper_i + s0/r_i)
S1 = min_i(lower_i + s1/r_i)
~~~

这里的 8 ms 是当前选择的容差常量，不是跨设备精度保证。自身确认来源不明时不能伪造标定。
观测延迟并不自动等同端到端物理输入延迟；显示的网络 RTT、视觉反应时间也不能直接加进来。

## 5. 时间窗对齐：现在、下一步或跳过

通用辅助函数 `CopydogDynamicParryWindow` 可表达附加延迟区间 `[q0,q1]`：

~~~text
L = c1 - q0 - S1
U = c0 - q1 - S0
preferred = (L + U)/2
~~~

它表示希望自身有效段覆盖候选时间带时，提交延迟 `d` 的数值边界。
当前诊断路径的 `[S0,S1)` 已折入上一节补偿，因此调用该函数时使用 `q0=q1=0`，避免重复补偿。
`preferred` 是计算出的参考中点，当前帧决策并不只检查是否命中这个中点。

端点不能一律写成闭区间：单点候选 `c0=c1=T` 对应

~~~text
T - S1 < d <= T - S0
~~~

左边严格不等号来自自身有效段的半开结束。
许可段模式与 onset-only 模式通过 `includeLower` 区分下边界；不能把这个参数丢掉后宣称边界行为完全相同。

`CopydogParryFrameChoiceBounds` 比较 `d=0` 和 `d=h`：

1. 区间无效、已经错过等情形跳过；尚未到窗口或下一步估计不可用则等待。
2. 现在可行而 `h>U`，现在提交，避免在预计下一步错过上界。
3. 两个观察点都可行时，比较边界余量 `M(d)=min(d-L,U-d)`；现在余量不小于下一步则现在提交，否则等待。

“跳过”不总表示永久把这个动作列入黑名单；最终返回还会考虑关闭状态、重复攻击、当前可读性和队列检查。
最终提交前再次核对最新相位、目标身份、装备、动作名称、自身受击/死亡以及队列归属，避免拿过期计划直接出手。

### 一个直观的离散时机例子

以下是假设有效段为 `[100,140)` 的单点候选演示，单位 ms；并非声明所有工具使用这组参数。
补偿已经折入该有效段。

| 剩余候选时间 T | 下一步 h | 候选提交边界 (L,U] | 时间计划 |
|---|---|---|---|
| 130 | 11.76 | `(-10,30]` | 等待：下一步的边界余量更大 |
| 118.24 | 11.76 | `(-21.76,18.24]` | 现在：再等一步的余量更小 |
| 130 | 40 | `(-10,30]` | 现在：预计下一步将超过 U |
| 150 | 60 | `(10,50]` | 等待：现在尚不可行；不能声称提前乱按就能覆盖接触 |

最后一行说明离散更新的物理限制：下一次更新若真的很晚，窗口可能整体被跨过；
仅靠在当前不可行时抢先提交，无法数学保证成功。
表格只说明时间选择，最终状态或队列拒绝仍会阻止提交。

## 6. 保留的连续碰撞模型算什么

核心在 `prediction_geometry.c`。胶囊体用线段端点和半径表示。
两条轴线段最短距离减去两个半径得到间隙：

~~~text
g(t) = distance(segmentA(t), segmentB(t)) - radiusA(t) - radiusB(t)
~~~

若在一个时间区间 `[l,r]` 上，`V` 是该模型间隙变化率的有效上界，代码用下面的保守下界排除整段：

~~~text
lower = min(g(l), g(r), (g(l)+g(r)-V*(r-l))/2)
~~~

当 `lower` 大于接触容差，才能认定该模型在整段内清空。
否则分割区间，优先搜索左侧，保留更早可能接触的区间；这不同于只看中点是否重叠就决定丢弃哪一半。

- 线性模型：端点和半径插值，按端点移动与半径变化建立速度界，先做扫掠包围盒粗筛。
- 旋转模型：对骨骼臂向量使用轴角旋转，再叠加 pivot 平移、角色 yaw 和 root 平移；速度/加速度界来自该外推模型。
- 旋转外推依赖当前测得的运动率，不是读取任意未来完整动画，也不是两个姿态可精确恢复所有刀路的保证。
- 搜索结果区分 `CONTACT`、`CLEAR`、`POSSIBLE`、`UNKNOWN`；预算耗尽、无效形状或证据不足不能改写成确定无碰撞。
- `CD_PRED_TOLERANCE_MS=0.05` 是搜索时间区间宽度阈值，**不是 CPU 耗时 0.05 ms**，也不是相对于真实游戏接触的绝对误差保证。
- 调用方提供有界采样预算；`CD_PRED_WORK_BUDGET=32768` 不代表测得整个游戏帧耗时。

以上排除与接触结论以输入形状、运动模型及其速度界成立为前提。
形状不准、动画取消、未来转向变化、网络回滚和预算限制都会影响真实表现。
当前自动弹反不拿该接触结果作为最终出手依据，不能因为预测计数增长就推断本次弹反由 CCD 决定。

## 7. 弹道与地面范围威胁

`combat_core.c` 的基础弹道接触使用相对运动：

~~~text
x(t) = (projectilePosition-playerPosition)
     + (projectileVelocity-playerVelocity)*t
~~~

对球形端帽求 `|x(t)|²=R²` 的最早非负根，并结合直立胶囊体的中间圆柱段。
实现使用稳定的根与叉积距离形式，减少远距离擦边时相近大数相减的误差。
该基础模型在所求区间使用恒定相对速度，不能把它写成完整任意弹道物理模拟。

`projectile_area_geometry.h` 对静止中心、可线性增长半径的范围形状与移动中的玩家胶囊体求接触。
它按最近轴段区域和半径斜率变化分段，解每段的二次接触条件；寿命结束与预测端点分别处理。
其它子弹/范围代码再结合已知参数、延迟生成、地面候选和观察记录组织威胁。
地形估计、子弹族与触发事件有覆盖边界，不声称所有战技/爆炸均支持。

翻滚方向可以选择避开飞行线的侧向，并考虑玩家当前移动；没有完整导航网格或地形安全保证。
原按键和动作仲裁仍有效：F7 控制翻滚，按住 Shift 暂停自动翻滚，已占用的动作队列先排空。
