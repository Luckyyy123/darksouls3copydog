# PvE 专用分支路线

维护者明确欢迎 PvE 改造。当前仓库不是一个已经适配所有 NPC 的 PvE 成品。

## 1. 先拆目标适配

把玩家槽枚举、NPC/敌人枚举、阵营、死亡、脱战与世界切换整理成独立目标适配层。
不要将 PvP 武器 ID、单双持规则和玩家动画表直接套给 Boss/NPC。
已有锁定 NPC 的观察入口只是连接点，不代表 NPC 攻击许可和时间模型已经齐全。

## 2. 处理本地时间与网络路径

PvE 决策应使用本地动画/世界时钟，明确暂停、卡顿、加速和动画重启的语义。
审查并拆离不需要的 peer 延迟、玩家网络 ID、发送/接收包 hook、联机复制等路径；
保留或删除时确认 hook 注册、接收桥和卸载生命周期完整，不能只屏蔽回调主体。

## 3. 建 NPC 攻击资料与许可

按敌人、动作、可弹许可、伤害/范围事件建立可追溯数据。不可弹、未知与无接触分别处理。
盾牌/工具有效段、可被弹反许可和真实接触仍是不同数据，不要用一个宽泛动画后缀代替。
缺模型时不要默认为立即出手，也不要把每个未知动作永久写死为不可弹。

## 4. 恢复几何授权前先补证据

对当前姿态、武器/身体形状、移动/旋转、可信预测时长和连续接触提供独立用例。
验证后再决定何时将几何证据接回自动弹反授权，保留 UNKNOWN 与预算耗尽的诊断。
两帧端点不能精确恢复任意刀弧；合成测试不能代替真实接触标签。

## 5. 保持动作队列和回归

覆盖多敌人优先级、连续攻击、翻滚恢复后再次防御、背刺/处决占用、取消、世界切换和角色受击。
用有限预算测试 30/60/85/144 FPS 及卡帧；分别报告模型正确性、实机命中效果和耗时。
提交改造时明确支持的敌人/动作、已测条件、缺失数据和许可来源。
